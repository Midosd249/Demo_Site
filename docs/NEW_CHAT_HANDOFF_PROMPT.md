## Engineering protocol

For behavioral changes:
1. Inspect existing test/build setup.
2. Add a failing regression test first.
3. Implement the smallest useful change.
4. Refactor after green.
5. Run the full available test suite.
6. Verify the deployed runtime.
7. Check console/network/layout/accessibility where tooling permits.
8. Do not claim browser QA if only source inspection was performed.

## Visual red-team before completion

Before declaring a site finished, inspect it as if you were a demanding prospect seeing it on a phone.

Ask:
- Does the first viewport look expensive?
- Does the site communicate the business in seconds?
- Is the image doing meaningful visual work?
- Is typography carrying hierarchy?
- Does the page have rhythm?
- Does scrolling reveal a story?
- Is the CTA obvious?
- Does the mobile layout look intentionally designed?
- Does it look like a real business website rather than a generated template?
- Would I confidently show this to a Riyadh business owner?

If not, keep working.
